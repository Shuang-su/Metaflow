# Aave Glass 本地研究包：使用流程与代码说明

## 现在的使用流程

1. 启动本地服务：

   ```bash
   python3 -m http.server 4173 --directory /Volumes/Prism/Metaflow/aave-liquid-glass-lab
   ```

2. 打开 `http://127.0.0.1:4173/`。
3. 页面会自动进入 `/design/building-glass-for-the-web/`，这是从原站 SSR/Flight HTML、CSS、JS chunk、图片、视频生成的本地镜像。
4. 用这个镜像做 1:1 对照：布局、section 顺序、switch/slider/toggle 行为、QR canvas、video WebGL 控制层、map playground。
5. 默认入口现在不再加载自定义 `mirror-fixes`。Next hydration 会正常启动，原站 React 事件、Framer Motion、SVG filter 和 WebGL 路径自己接管。
6. 需要看可复现规范时，阅读 `WEB_LIQUID_GLASS_SPEC.md`。旧的手写 demo 已删除，不再作为任何实现依据。

## Storybook 研究册

启动 `Web Liquid Glass：原理与实现`：

```bash
npm --prefix /Volumes/Prism/Metaflow/aave-liquid-glass-lab/storybook run storybook -- --host 127.0.0.1 --port 6006
```

Storybook 使用标准 preview，不加载完整文章页面。`src/origin/runtime.ts` 会在首次访问时加载一次本地 Turbopack runtime 和锁定的 chunks，拦截 Next 页面入口 `95395`，然后根据当前 story 直接挂载原始组件模块。切换 Switch、Slider、Toggle、QR、Video 或 How It Works 时，只卸载当前组件并挂载目标组件，不导航到 Hero，也不刷新 preview。

页面内只保留组件演示和研究正文；Back、目录、Share、Aave 顶栏和原页面主题按钮不会进入 preview。全局 Light/Dark 按钮位于 Storybook 左侧栏底部，同时同步 manager、preview 和原始 `ThemeProvider`。

`scripts/generate-study-pages.mjs` 现在只生成两类结构化证据：

- `src/generated/origin-manifest.json`：runtime、chunk、模块 ID 和桥接配置。
- `src/generated/study-content.json`：原文说明、运行指标、真实 chunk 片段和复现规则。

它不再生成 `public/study/` 文章副本。Storybook、TypeScript、npm 和 Playwright 均通过 `scripts/run-local.mjs` 把缓存与临时文件固定到外置磁盘的 `storybook/.cache/`。

## 为什么删除旧 demo

镜像最接近原站，但它是压缩后的 Next/Turbopack 运行产物，适合取证和比对，不适合直接复用到其他项目。

之前的手写 demo 是早期近似复刻。它在视觉层、DOM 结构、filter target、WebGL 细节上都和原站最终实现有差距，继续保留会误导后续判断。

现在保留的是事实来源：

- 原站镜像：验证 layout、motion、DOM wrapper、filter counts、canvas/video 行为。
- raw chunks：反查真实组件参数、filter 结构、shader 路径。
- runtime metrics / live summary：记录运行态尺寸、计数和浏览器行为。
- `WEB_LIQUID_GLASS_SPEC.md`：把上述证据归纳成可重写规范。

规范要保留的是实现模型：

- DOM 组件：`data-aave-glass-container` 包住真实内容和 refraction target。
- 折射核心：生成 lens-sized PNG displacement map。
- SVG 路径：把 map 塞进 `feImage`，通过 `feDisplacementMap` 折射目标层。
- 控件路径：switch/slider/toggle 只移动 filter region，不在每次 pointer move 重新生成 map。
- canvas/video 路径：同一张 map 上传为 WebGL texture，shader 折射视频或 canvas 像素。

## 这次空白、椭圆和交互失效的结论

用户截图里的问题不是原站资源没有抓全，也不是 Safari/Chromium 能力差异造成的。

真正根因是本地化时只改了 HTML 里的 `<script src="/design/_next/...">`，但 Turbopack runtime chunk 内部仍硬编码：

```js
let t = "https://aave.design/design/_next/";
```

Turbopack 用这个 base 拼接 chunk key。结果本地虽然加载了 `/design/_next/static/chunks/...`，runtime 仍按远程 URL 判断依赖，入口 `runtimeModuleIds:[95395]` 没有执行，Next hydration 没启动。

未修复前的运行态证据：

- `window.next === false`
- `__next_f.length === 28`，Flight 队列没有被消费；
- body、slider、toggle、video button 上没有 `__reactFiber` / `__reactProps`；
- switch 只是原生 checkbox 被点中，slider/toggle/video 的 React 行为不工作。

因此出现：

- switch/slider 等 demo 区域有内容但被隐藏，看起来像空白；
- 首屏右侧的玻璃 lens 存在但不动，覆盖在浅色背景上时肉眼像椭圆；
- 核心 glass DOM 仍然存在，运行态仍可看到 `5` 个 `[data-aave-glass-container]`、`25` 个 SVG `filter`、`35` 个 `feDisplacementMap`。

现在的修复是：

- 默认 HTML 改为使用 `reference/origin/server-raw.html` 本地化后的 SSR/Flight stream，而不是 post-hydration DOM 快照；
- 将 `turbopack-5725b656aea77f16.js` 里的 chunk base 改为 `"/design/_next/"`；
- 默认页面实际引用 `turbopack-5725b656aea77f16.local.js?dpl=...`，这是同一份已修补 runtime 的本地文件名副本，用来绕过浏览器旧缓存；
- 不能通过给 runtime script 额外追加 `&local=...` 这类 query 来清缓存，因为 Turbopack 会把 `document.currentScript.src` 的 query 当作 chunk suffix 参与匹配，query 变了会导致 React 启动但 glass filter 子节点不完整；
- 不再注入自定义 `mirror-fixes`；
- 让原站 `appBootstrap -> hydrate -> hydrateRoot` 自己消费 `__next_f` 并挂载事件。

修复后的验证：

- `window.next === true`
- `__next_f.length === 0`
- slider、toggle、video button 都有 React fiber/props；
- switch、slider、toggle、video 的同一时序交互结果与线上原站一致。
- in-app browser 刷新后也恢复到 `25` 个 `feImage`、`35` 个 `feDisplacementMap`；首屏 moving lens 是 `160x160`，slider/code 区不再空白。
- QR/canvas 点击后 canvas 像素签名变化，说明原站 WebGL/canvas 折射路径本地可运行。
- map playground 拖动 Width 后，`feImage` 的 `x/width` 从 `0.2968/0.4064` 变为 `0.1506/0.6988`，右侧 displacement map data URL 长度从 `123162` 变为 `105382`，说明参数面板会重新生成 map。
- 移动端 `390x844` 从首屏到底部 `scrollWidth === clientWidth === 390`，没有横向溢出；glass/filter/canvas/video 计数保持 `5/25/4/2`。

## 原站 DOM 路径

原站 DOM 组件的关键结构是：

```html
<div data-aave-glass-container>
  <div style="will-change: filter">...</div>
  <div class="refraction-target" style="filter: url(#...)">...</div>
  <svg>
    <filter>
      <feImage result="rawMap" />
      <feColorMatrix result="scaledMap" />
      <feDisplacementMap in="SourceGraphic" in2="scaledMap" />
    </filter>
  </svg>
  <div class="lens-visual"></div>
</div>
```

switch 和 slider 的原站重点不是简单给整个组件加 filter，而是额外建一个目标层：

- switch 外层真实尺寸是 `74x28`。
- glass container 是 `116x70`，`margin:-21px`。
- 被过滤的 refraction target 是 `232x140`，再 `transform: scale(0.5)`。
- 目标层用 `clip-path` 限制到把手区域。

slider 同理：

- track 是 `240x22`。
- glass container 是 `290x72`，`margin:-25px`。
- refraction target 是 `580x144`，再 `scale(0.5)`。
- 镜片移动时更新 `feImage x/y/width/height` 和 clip-path。

toggle group：

- glass container 的视觉 rect 约 `584.73x206`。
- 实际内容高度 `46px`，padding 是 `80px 40px`。
- lens 是选中项大小，例如首项 `87.05x40`，只在选中项里移动。

## Displacement Map 怎么写

map 是 lens-sized PNG，不是整页截图。红绿通道保存位移方向：

```js
shellMask = 0.5 * (1 + erf((signedDistance + depthPx) / (depthPx * Math.SQRT2)));
red = (0.5 - 0.5 * normalX * shellMask) * 255;
green = (0.5 - 0.5 * normalY * shellMask) * 255;
blue = 128 + specularOrEdge;
```

迁移时要注意：

- `depth` 在原站组件里经常是像素值，例如 switch 的 `depth: 2`。
- `lensW/lensH` 在 React 参数里常表示半尺寸；实际 DOM lens 是两倍后的位置关系。
- `scaleX/scaleY` 会通过 `feColorMatrix` 把 map 的 R/G 拉回中性 0.5，控制折射强度。
- `feDisplacementMap scale` 在原站 objectBoundingBox filter 下是小数，例如 switch 约 `0.25/0.275/0.3` 三个 RGB pass。

## WebGL 路径

QR 和视频不能只靠 DOM SVG filter。

QR：

- QR 自身画在 canvas。
- 点击 Aave logo 时生成同一类 displacement map。
- WebGL shader 用 map 的 R/G 偏移采样 QR canvas。

Video：

- 原站 live `<video>` 作为 texture 输入。
- 控制按钮和进度条每个都有自己的 lens 区域。
- shader 有 source texture、map texture、blurred texture、circle lenses、bar lens、specular/adaptive brightness。
- Safari 对 live video 的 SVG filter 不可靠，所以视频必须走 WebGL。

## Safari 为什么原站效果是全的

之前页面里的说明写错了：问题不是 Safari 不支持最终方案，而是 Safari 不适合某些早期 prototype 路径。

原站最终方案之所以在 Safari 完整，是因为：

- 普通 DOM 走 SVG `feDisplacementMap`，不是 Chromium-only 的 backdrop capture。
- 视频/canvas 走 WebGL，不依赖 Safari 把 live video 交给 SVG filter。
- Safari filter 缓存问题通过刷新 filter id / map href 处理。
