# Web Liquid Glass：原理与实现

从镜片几何、generated displacement map 到 DOM/SVG 与 WebGL，这本研究册给出一套可以运行、阅读、测量和修改的 Web 液态玻璃实现。

## 先区分四种内容的职责

为了既保留可核对的效果，又真正得到可修改代码，本册同时存在四层内容。它们互相校验，但不能互相冒充。

| 层级 | 用途 | 能证明什么 | 不能单独证明什么 |
| --- | --- | --- | --- |
| 锁定交互基准 | 操作目标行为、读取运行态 | 目标视觉、真实参数、DOM/Canvas/Video 结构 | 我们已经掌握并重写了实现 |
| 独立 TypeScript / GLSL | 阅读、修改、扩展 | 算法与生命周期可以脱离构建产物运行 | 所有浏览器、所有动画帧都已像素级一致 |
| 格式化实现片段 | 校核参数和关键路径 | 研究结论有具体实现依据 | 压缩变量名或构建文件名适合成为公共 API |
| 运行验收记录 | 比较 bbox、map、状态与像素 | 当前代表状态已经通过哪些检查 | 未执行的 Safari、长时间播放或逐帧差分也已完成 |

因此，**截图相似不是完成，直接调用基准模块也不是独立实现**。完整证明至少要覆盖状态、几何、map、渲染节点、交互和像素输出。

## 先建立正确的模型

玻璃不是盖在内容上的透明模糊层，也不是一张被裁切的背景截图。内容先正常绘制；镜片几何生成 displacement map；渲染器再根据 map 的 R/G 通道回到 source 中重新采样像素。B 通道保存方向性高光，A 通道在 WebGL 路径中限定镜片边界。

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| Geometry | `lensW`、`lensH`、radius、depth、dome、splay | 镜片 SDF |
| Lens Map | SDF 与曲面梯度 | R/G 位移、B 高光、中性灰外部 |
| DOM | live DOM + map | SVG `feImage` + `feDisplacementMap` |
| Canvas / Video | source + map + blur textures | WebGL output |
| Interaction | native input / media events | position、geometry 或 uniforms 更新 |

这条数据流决定了最重要的性能边界：**位置变化不重建 map，形状或材料变化才重建 map。**

## 1. 从镜片几何生成 Map

实现从 rounded-rect SDF 开始。每个像素先计算到镜片边界的有符号距离，再计算 dome gradient、edge falloff 与 splay。算法只写左上象限，然后镜像到另外三个象限，同时翻转 R/G 的符号。

<GuideCodeBlock sourceId="lens-map" label="当前运行的 TypeScript Core" />

必须保持以下编码契约：

- `R = 128` 表示 X 不位移；大于 128 向一个方向采样，小于 128 向相反方向采样。
- `G = 128` 对 Y 使用相同规则。
- `B = 128` 表示没有额外高光；更高的值来自 glow 或 edge specular。
- DOM map 的镜片外保持不透明中性灰；WebGL map 的镜片外使用透明中性灰。

## 2. 把 Map 接到 DOM

DOM 路径不复制整个页面。组件提供真实的 `data-refraction-target`，控制器为它建立五槽 SVG filter pool：一个 rich filter 与四个 target slots。`feImage` 载入 map，`feDisplacementMap` 消费 R/G，filter region 只覆盖镜片与 bleed。

<GuideCodeBlock sourceId="svg-controller" label="当前运行的 SVG Filter 控制器" />

移动镜片时只更新 filter region、mask 与 visual shell 坐标。`lensW`、`lensH`、radius、depth、curvature 或 splay 改变时，才让 map cache 失效。这样拖动不会持续编码 PNG，也不会反复创建 SVG 节点。

## 3. 把同一模型接到 Canvas 与 Video

Canvas 和 Video 已经是像素表面，内部内容不能再作为 live DOM 交给 SVG filter。WebGL renderer 因此维护 source、map 和可选 blur texture，并在 fragment shader 内执行相同的采样位移。

<GuideCodeBlock sourceId="webgl-shader" label="当前运行的 WebGL shader" />

视频按钮和进度条可以共享同一 source/blur texture，但各自保留 circle 或 bar lens。QR 则进一步把点阵矩阵上传为 occupancy texture，并在 shader 内解析 finder-eye SDF，避免把二维码先烘焙成低分辨率截图。

## 4. 让交互保持原生语义

玻璃层只负责派生视觉，不保存第二份业务状态：

- Switch 继续由 native checkbox 管理 checked、focus 与键盘。
- Slider 继续由 native range 管理 value、step 与方向键。
- Segmented Toggle 使用真实 button 管理选择和焦点。
- Video 使用真实 media events 管理 play、pause、seek 与进度。

状态先变成规范化 progress，再同时驱动真实 fill、镜片位置和 filter bbox。按住或速度产生的 rubber deformation 属于镜片几何，结束后通过 spring 回到静止形状。

## 跨浏览器边界

<div className="winner-table">

| Approach | Chromium | Safari | Firefox |
| --- | --- | --- | --- |
| SVG `backdrop-filter` | ✓ | ✕ | ✕ |
| HTML-in-Canvas API | 需开启实验 flag | ✕ | ✕ |
| Generated displacement map | ✓ | ✓ | ✓ |

</div>

Safari 可以呈现完整效果，是因为 DOM 使用 SVG displacement，Canvas 与 Video 使用 WebGL，而不是依赖 Chromium 独有的背景抓取能力。Safari 还需要 tight filter region、filter id refresh，并避免把 live video 直接交给 SVG filter。Firefox 走相同的最终数据模型，但仍需单独检查 SVG filter bbox 与色彩空间。

## 从错误路线纠正出的工程规则

下面这些问题都曾经产生“局部看起来可用”的结果，但无法支持后续修改。保留这张表，是为了以后遇到相同症状时直接回到根因，而不是再次从表面补丁开始。

| 早期路线或症状 | 为什么会误导 | 后来的修正 | 以后必须坚持 |
| --- | --- | --- | --- |
| 用 blur、透明度和边框近似玻璃 | 能做出材质感，却没有实时像素折射 | 先生成 displacement map，再由 SVG/WebGL 重采样 source | 先证明 map 和像素变化，再调 shell |
| clone overlay 漂在组件外 | 复制层依赖页面坐标，host、bleed 与 target 不同源 | target、filter region、shell 全部进入 glass container 局部坐标 | resize/滚动/竖屏都读取真实 bbox |
| Hero 的圆形 shell 内出现正方形模糊 | border-radius 只裁了表面，filter/mask/blur 仍是方形 | 圆形 SDF、mask、bbox 和各向异性 blur 同步 | 同时检查 clip-path、filter bbox 与 X/Y blur |
| 整页 iframe、镜像裁切或 hydration 后再删 DOM | 切换时会先闪 Hero、产生加载延迟，内置浏览器还可能崩溃 | Storybook preview 直接挂载组件；页面不再创建嵌套 iframe | preview 内 iframe 数量必须为 0 |
| 只运行锁定构建模块 | 行为正确，但代码仍不可读、不可迁移、不可扩展 | 保留基准对照，同时建立独立 TypeScript/GLSL | 独立目录静态禁止依赖 origin runtime |
| 单独写一个“可调近似 Playground” | 参数同名但算法不同，实验结论无法回到组件 | Playground 与组件共享 map generator 与 controller | 相同参数必须得到相同 map signature |
| 把 Safari 写成不支持 | 混淆了实验 API 与最终 generated-map 路线 | 按 DOM/SVG、Canvas/WebGL 的最终管线描述兼容性 | 兼容性结论必须带 API 与路径 |
| 普通案例暴露 Storybook Controls | 参数入口与页面原理脱节，读者看不到 map 和缓存边界 | 普通案例固定参数，只有 Playground 使用页面内调节器 | 调节器必须与结果和 map 同屏 |
| 用隐藏演示伪装 README | 内容与案例重复，导航类型和读者预期都错误 | README 使用真实 MDX Docs entry | Docs 与 Story 语义分开 |
| 标题中的半角 `/` 随意出现 | Storybook 把它解析为额外目录，QR 导航被错误分层 | 展示名使用全角 `／`，路径层级只由有意的 `/` 创建 | 修改标题后检查 index 结构 |
| 全局覆盖 `pre span` 颜色 | Shiki token 全部退化为单色 | 保留 token style 与 Light/Dark CSS 变量 | 构建后检查至少四类 token 颜色 |
| Markdown 表格显示成 pipe 文本 | MDX 没启用 GFM 或 table 没进入共享 wrapper | 启用 remark-gfm 与 rehype table wrapper | 每次构建检查真实 table 数量与横向滚动 |
| 移动端用负 margin 拉宽演示 | 画面贴边、正文溢出，窄屏看似“更大”但不可读 | 统一 `24px` 页面边距和容器内响应式尺寸 | 390px 下内容宽度不得超过 342px |
| 用构建 chunk 文件名做正文标题 | 数字文件名只能定位证据，对读者没有语义 | 正文使用“SVG Filter 控制器”等语义名，chunk 只保留在元数据 | 构建标识不进入公共概念模型 |

## 固定的验收阶梯

修复不能停在“肉眼更像”。应从低成本、确定性的证据开始，逐层向真实交互和跨浏览器推进。

| 层级 | 检查 | 失败时先回到哪里 |
| --- | --- | --- |
| 1. State | checkbox、range、button、media state 是否真实变化 | 组件状态与事件绑定 |
| 2. Geometry | host、target、lens、filter bbox 是否同一坐标系 | wrapper、测量、DPR、resize |
| 3. Map | R/G/B/A、neutral region、signature、cache key | SDF、material、map generator |
| 4. Renderer | feImage/feDisplacementMap 或 source/map/blur textures 是否有效 | filter pool、shader、texture lifecycle |
| 5. Interaction | click、hold、drag、release、seek、visibility 是否同步 | 状态机、pointer capture、spring、RAF |
| 6. Environment | desktop/mobile、Light/Dark、Chromium/Safari 是否一致 | 浏览器分支、bbox、色彩空间、资源加载 |

## Storybook 本身也有实现边界

- 左侧导航负责阅读路径，preview 负责运行案例；案例内部不再嵌套另一张网页。
- README 是解释与索引，**构建与代码** 是独立实现教程，锁定基准只用于同页对照。
- 普通案例不提供 Controls、Actions、Interactions；参数实验使用页面内部控件。
- 页面主题由 Storybook 侧栏的全局按钮统一控制，manager、Docs、preview 和组件材料必须保持同一状态。
- 正文宽度、字号、表格、代码高亮和移动端边距属于研究结果的一部分，不能用临时全局 CSS 破坏。
- npm、Storybook、TypeScript 与浏览器测试缓存固定写入项目 `.cache/`，避免外部运行环境影响构建稳定性。

## 实现完成的判据

- DOM 组件必须出现真实 `feImage`、`feDisplacementMap`、filter pool 与 refraction target。
- 相同几何和材料输入必须生成相同的 map 像素；位置变化不得改变 map signature。
- Switch、Slider 与 Toggle 的 native state 必须和玻璃位置同步。
- QR 点击、Video 播放和参数实验后，WebGL 或 Canvas 的像素签名必须变化。
- 桌面与竖屏下 filter bbox 不裁切，圆形镜片不被拉成椭圆，页面没有横向溢出。

## 阅读顺序

1. 在 **1. 组件案例** 操作目标效果，再跟随“构建与代码”运行可修改实现。
2. 从 Switch、Slider、Toggle 理解 DOM/SVG 路径与原生输入同步。
3. 在 QR 与 Video 的 **WebGL 管线** 中理解 texture、DPR、frame loop 与资源释放。
4. 最后进入 **2. Playground**，同时观察折射结果、map、粒子和参数变化。
