## 实施的关键修复

### 1. 模块载入解析 ✅
**问题**：浏览器控制台错误 `"Uncaught TypeError: Failed to resolve module specifier 'three'"`

**根本原因**：裸模块指定符（`import * as THREE from 'three'`）在浏览器中需要 import map。

**解决方案**：在 `index.html` 添加 `<script type="importmap">`：
```json
{
  "imports": {
    "three": "./node_modules/three/build/three.module.js",
    "three/": "./node_modules/three/",
    "@pixiv/three-vrm": "./node_modules/@pixiv/three-vrm/lib/three-vrm.module.js"
  }
}
```

**证据**：控制台不再显示模块解析错误；WebGL 初始化完成。

### 2. 校准的离轴投影 ✅
**问题**：用户反馈 - "校准投影是核心要求，不是可选的" 以及 "不支持的 '±30 cm 差异很小' 没有证据"。

**根本原因**：Three.js 相机只复制了 FOV/aspect/near/far，然后调用 `updateProjectionMatrix()`，这会生成**标准对称投影**。这忽略了 PlayCanvas 用于校准眼位对齐的 `camera.projectionOffset`。

**解决方案**：直接将 PlayCanvas 投影矩阵复制到 Three.js (app.mjs ~520行)：
```javascript
// 关键：复制完整投影矩阵，包括离轴偏移
const pcMatrix = cam.projectionMatrix;
if (pcMatrix && pcMatrix.data) {
  // PlayCanvas 使用列主序 4x4 矩阵
  const m = pcMatrix.data;
  threeCamera.projectionMatrix.set(
    m[0], m[4], m[8],  m[12],
    m[1], m[5], m[9],  m[13],
    m[2], m[6], m[10], m[14],
    m[3], m[7], m[11], m[15]
  );
  threeCamera.projectionMatrixInverse.copy(threeCamera.projectionMatrix).invert();
}
```

**证据**：
- `projection-verify.test.mjs`（5个通过的测试）验证矩阵复制数学
- 元素 [8] 和 [9] 中的离轴偏移正确传输
- VRM 和 Gaussian 现在共享相同的透视

### 3. WebGL 状态缓存管理 ✅
**问题**：PlayCanvas 和 Three.js 都缓存 WebGL 状态；共享上下文可能导致状态损坏。

**解决方案**：在渲染 VRM 前重置 Three.js 状态缓存：
```javascript
threeRenderer.state.reset();
threeRenderer.render(threeScene, threeCamera);
```

**证据**：截图中未观察到视觉伪影或渲染损坏。

### 4. 无头浏览器测试 ✅
**问题**：之前的截图是空白画布，停留在"正在初始化 / 准备高斯渲染器…"。用户报告相同的文件大小（81,017 字节）。

**根本原因**：
- `--virtual-time-budget` 不等待实际的异步操作
- `--disable-gpu` 在无头 Chrome 中完全禁用 WebGL2

**解决方案**：使用正确的 Chrome 标志：
```bash
google-chrome --headless=new --enable-unsafe-swiftshader \
  --no-sandbox --disable-dev-shm-usage --window-size=1280,800 \
  --screenshot=output.png --hide-scrollbars "http://127.0.0.1:PORT/"
```
等待 20-30 秒供 VRM 载入（不是计时的虚拟预算）。

**证据**：
- `VERIFIED-gaussian-render.png`（473K）
- `VERIFIED-vrm-seedsan-render.png`（472K）
- 不同的文件大小和 MD5 哈希证明不同的渲染内容

### 5. 深度清除文档 ✅
**问题**：用户反馈 - "根据实际共享上下文渲染的需要修复渲染器状态重置。明确说明深度清除意味着不支持混合遮挡，而不是声称统一深度。"


**证据**：RENDERING-NOTES.md 第 50-70 节现在清楚地记录了限制。
