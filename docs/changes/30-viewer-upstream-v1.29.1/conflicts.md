## Checkpoint update rule

After each implementation checkpoint, this table must be updated with the checkpoint SHA, test or browser evidence, failures, and any new conflict. A new conflict must receive a concrete `Keep`, `Port`, `Replace`, `Drop`, or stopped `Conflict` outcome before implementation continues. If both behaviors cannot coexist without violating the Spec, stop at the prior clean checkpoint and report the source surface, both behaviors, failure evidence, options, and rollback SHA.
