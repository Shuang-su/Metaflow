# MF-70：单人头显沉浸漫游

状态：Accepted / Implementing。组件：Viewer；风险 T2。Issue：[MF-70](https://github.com/Shuang-su/Metaflow/issues/70)。实现分支：`codex/xr-immersive-roaming`。

唯一 Plan 是 [Codex 任务](codex://threads/01a09044-33de-7380-a80d-fb37c20f5f8b)中用户确认的《MetaFlow：接近 VRChat 操作质感的沉浸漫游》。本文件定义行为契约，不复制实施 Plan。验收记录见 [verification.md](verification.md)。关联 #51、#54、#65；不改变这些任务的范围。

## 进入、尺度与追踪

软件导航只变更相机父节点，保留浏览器提供的头部位姿。首次有效 XR 帧将用户头部对齐进入前的场景位置和水平朝向；沿用资产尺度，不缩放世界。若有碰撞，在进入位置附近最多 1.5 米范围搜索已加载、可站立且有身体空间的地面。碰撞尚未就绪或没有合法地面时暂停软件步行，明确提示手动校准或选择合法瞬移落点；后续加载不突然拉动视角。

站姿采用真实追踪高度，坐姿用父节点高度偏移将校准时眼高设为 1.65 米；头部追踪仍然持续。回起点恢复起始地面与水平朝向，保留当前真实头高。浏览器报告 `emulatedPosition` 时告知仅有旋转追踪，不伪造 6DoF，不宣称能修复系统定位。

## 操作

- 两个手柄：左摇杆移动，右摇杆转向。保留模拟力度、圆形死区与斜向限速；移动方向使用头部朝向在地面的投影。转向绕当前头部位置进行。
- 用户追加的单右手柄支持：纵向前后移动，横向转向；握住侧键时横向改为平移。左手柄恢复后自动使用双手柄布局。
- 默认连续移动与连续转向。舒适模式使用经过碰撞验证的瞬移及 30° 分段转向。无碰撞场景明确为自由漫游，不绘制或生成虚假地面。
- 有碰撞时，软件步行检查地面坡度、台阶、墙体、身体净空及碰撞分块加载状态；保留物理头部位移，不强制纠正视角。
- 浏览器手部／注视输入：使用标准选择事件。无摇杆的手部输入不能因为附带 `gamepad` 按钮而误判为手柄。有地面时指向并选择合法落点；无碰撞时持续选择沿射线的水平朝向缓慢漫游。松开、取消、追踪失效和会话隐藏立即停止。
- 模型复用引擎现有手柄和手部资源，加载失败显示追踪点。无关射线在漫游时隐藏；菜单和瞬移显示指向反馈。

## 空间菜单与生命周期

菜单打开后停留在空间中，提供继续、回起点、站坐姿、校准、移动方式、说明和退出；AR 仅保留继续、说明及退出。菜单按键或小型唤出控件可重新打开菜单。打开时暂停摇杆移动；关闭／断连恢复后等待摇杆回中。菜单选择不会同时触发瞬移，`selectend` 取消不提交操作。

加载中不创建会话，进行中的请求不重复创建。取消授权、初始化错误、运行时中断、退出和重入均清理本轮输入与菜单，恢复进入前的相机、父节点、裁切和运行时画质。AR 失败有明确反馈，普通浏览继续可用。

## 画面与后端

XR 使用独立运行时设置：默认一百万 splat 预算，保留显式 URL budget 覆盖；更新颜色和 LOD 的视角阈值适合头部转动，近裁切为 3 厘米。退出恢复普通浏览值。纠正 PICO 在窗口与 XR 间切换 DPR 导致的低分辨率，使用浏览器原生推荐 XR 缓冲区大小；这不承诺原生分辨率下所有场景达到刷新率。

保留引擎 WebGPU XR 路径。设备只有普通 WebGPU、没有 WebGPU XR 绑定时提示使用 WebGL；不根据品牌推断支持。本轮不升级整个引擎，不实现 #54 的自动画质系统。

## PICO 浏览器窗口双手操作（追加范围）

用户明确针对 PICO 浏览器窗口的双手手势；手机／平板的既有双指逻辑不是本次重做对象。必须分别验证普通 DOM 指针／滚轮事件与沉浸 WebXR 输入。先记录真机实际事件，再决定适配：两个独立触点或浏览器捏合滚轮可接入既有缩放；若浏览器仅暴露单个鼠标指针，网页不能由此重建两只手。`maxTouchPoints`、`XRHand` 构造器存在及原生 SDK 的手势文档都不能替代真机证据。

此项在实际手势事件采集完成前保持待验证，不引入设备名强制切换，不宣称双手已通过测试。

## 边界与验收

不新增多人、化身、语音、抓取、传送门、AI 导览、AR 放置；不修改资源格式、分享地址或碰撞生成流程。独立分支和待审 PR 交付，不部署生产，不提升发布版本。

自动化覆盖力度、绕头转向、任意朝向瞬移、非法落点、菜单隔离、断连及状态恢复。真实设备验收仍要求 PICO 4 Ultra 系统 5.15.4／浏览器 4.0.38，在有碰撞、无碰撞和大型流式场景完成站坐、单右手柄、手势、舒适模式、退出重入及至少十分钟连续路线；记录改动前后同路线画面和应用帧间隔。Vision Pro 模拟器验证选择与生命周期，真机舒适度、追踪和性能独立标记未验证。

## 用户追加：局部碰撞体素可视化

在已有页面碰撞叠层开关上，补充 WebGL 与 XR 可用的局部体素线框。绘制实际已加载体素的表面单元，保持网格原有分辨率及坐标变换；不以抽样重建或空白分块伪造碰撞数据。显示范围限于相机附近，每次扫描有时间／数量预算，最多 2000 个单元，每批最多 256 个完整单元以避免当前 PICO 大批线框单眼缺失；关闭时不扫描。WebGPU 普通窗口保留原有 compute 叠层，XR 使用真正世界空间几何，避免将单眼屏幕叠层贴给双眼。空间菜单提供相同开关。此功能是检查工具，不默认开启，也不作为性能验收画面。

跳跃纳入后续独立待办，不在本轮静默加入：需要起跳／落地状态、重力、头顶与侧墙碰撞、分块缺失处理、单右手柄按键冲突规则，以及舒适模式可关闭策略；不得额外制造头部晃动或落地镜头动画。

## 交互可发现性与确认反馈（真机反馈修正）

用户找不到舒适模式入口，因此菜单按钮直接描述下一步动作（切换到舒适模式／连续移动、切换到坐姿／站姿），面板显示当前移动方式与姿态，不依赖用户猜测状态行可以点击。操作提示按单手柄、双手柄或手势输入选择。按住按钮时显示按下状态；成功菜单选择与有效瞬移在支持的手柄上尝试短震动，不支持或断连时不能阻断操作。

追踪丢失取消正在进行的选择；恢复前若有效位姿帧中断超过 250 ms，软件移动等待摇杆回中，避免继续执行中断前的长按。选择事件只查询事件帧的目标射线位姿，并要求最近 250 ms 内已有有效动画帧头部位姿；不得在输入事件帧调用仅限动画帧的 getViewerPose。用户明确要求本阶段优先交互，专项性能调优暂缓；既有性能指标保留，不改写为性能验收通过。
