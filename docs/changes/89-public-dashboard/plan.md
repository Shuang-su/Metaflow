# MF-89 · 唯一实施计划

依据用户批准的《Metaflow 轻量公开看板与 Metabase 按需运行方案》。唯一合约见 [spec.md](spec.md)。

1. 保护本地主分支和未跟踪文件，建立 Issue、隔离分支、Spec / Plan / PR。受磁盘容量限制，若完整 managed worktree 失败，使用只包含平台路径的 shared sparse clone，不复制 3D 资源。
2. 实现固定汇总函数、独立受限角色、公开资源白名单；通过合成事件验证去重、加权、P95、北京时间、无样本和权限拒绝，再与生产原始事件的独立查询对照。
3. 实现原子快照发布、轻量服务器采样、systemd oneshot / timer、静态 Caddy 契约；用失败注入和私密字段检测验证最后有效快照。
4. 实现 React / Vite 静态页面，真实聚合数据预览；验证桌面 / 手机、7 / 30 天切换、排序搜索、空 / 失败 / 过期状态。仅构建机运行 Node，服务器无常驻 Web 应用。
5. SSH 恢复后检查管理员、会话、API key、订阅、任务、事故遗留、云防火墙、持久化、版本；离机受限备份并恢复验证，完成安全升级。若异常未解释则暂停部署并记录重建需求。
6. 建立独立 Upptime 仓库与 Pages、监测新鲜度；独立 GitHub runner 验证 DNS / TLS / HTTP，不跳过证书校验。域名发布需确认 DNS 控制权限并读回。
7. 备份现有入口，发布静态页面与定时快照，Caddy 阻断所有管理路由；Metabase 内部保留。有限并发检查并核对无数据库调用。
8. 持续至少 24 小时正常快照与状态监测后，执行停用前测量、按需启停验证及最终停止；继续观察至少 30 分钟，记录真实资源变化。依赖未解决、快照中断或事故核对未过均不得自动停止。
9. 完成 PR 验收映射：代码、实测、未运行项、外部写入读回、观察起止、风险和回退；本地 checkpoint 并推送任务分支。未满足真实时间门槛时明确标记未完成。

验证命令、部署路径和恢复操作见 `analytics/dashboard/README.md`；本计划不改变 Viewer / Editor 版本，也不要求复制旧 MCL dossier。
